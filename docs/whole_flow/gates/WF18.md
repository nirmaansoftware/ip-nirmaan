# WF18

WF18 (the driver and its tests run in a process of their own with only the
HAL's calls carried across; the interrupt and bus-error tests still fail on a
broken design; the fixtures of the second addendum's decision 1 are recorded
again; before any second register block batch and before any whole-flow
figure leaves the repository's records). Council record
`council/records/2026-11-19-seat-c-live-refusal.md`, decision 2 (gate SC9),
adds one line to this gate:

> The nonce does not travel on a command line that the seat account can read,
> or a recorded probe shows it cannot read it.

2026-11-22, where the nonce travels today. `fw.test` gives the run's nonce to
the program it builds as a command-line argument (`+nirmaan_nonce=<hex>`,
`_cosim_steps` in `src/nirmaan/integrations/firmware.py`). In the live
evaluation jobs that argument is passed on through the seat wrapper, `sudo`
and the root helper (`exec_argv` in `scripts/live_eval_seat.py`), so it is on
the command line of each of those processes while the program runs; the run
step of each committed credential test record shows it
(`evals/flow/credential_test_record.json`,
`evals/flow/flow_rejudge_gate_record.json`, `run_step`). Whether the seat
account can read another process's command line is not probed: the
credential test has no such probe (the record's fact 11; that it is readable
is an assumption). The line is therefore not met today. Until WF18 is met it
adds nothing the seat can use that it does not already have: in checks 5, 6
and 7 seat C shares the harness's process, where it can read the nonce and
the pass counter (`docs/GATE_INTEGRITY.md`, section 3: the
address-arithmetic probe found both) and so could print a verdict line (an
inference from the sources, not run). Once the driver and its tests run in a process of their own, the
nonce must stay off any command line the seat account can read, or a
recorded probe must show it cannot read it, before this gate is called met.
