**The repository checks every committed slot record against the plan, for both cases (wave 2 close, meeting 2, decision M7, item 2; gate W2C24).** Gate WF29's check of a slot record against the plan's per-stage tables (fifth addendum to the G3 record, decision F3, item 3) was the private dispatcher's alone. `tests/test_whole_flow.py` now makes it on every committed whole-flow record, in the ordinary test job with no secret and no dispatch. It checks the slot's case and arm from the plan's section 10, then purpose, flow label, harness variant, case digest, fingerprint, CLI and replay flag against the latest values the plan states for that case. Then it checks the four items: the stage names in order; the seated stages first and every later one "not run" with nothing done; each seated stage's skills and digests, exactly; and the flow digest, recomputed and equal to the plan's digest over that many stages. A record whose case has no stage tables in the plan is refused, with no fall back to the other case's. The test shows a committed stopped record (timer slot 4) accepted and the four copies of decision F3, item 5 refused. It also shows the same on synthetic register block tables, adding firmware-engineer's two copies: the firmware stage's skill digest changed, and the firmware stage not run after a completed RTL stage. The table test now reads each case's rows by its case column, and each case's flow digests from that case's own values table (the `Case, <id>, case digest` row and the rows after it in its section). It covers the register block's rows once the plan states them, and until then refuses any committed register block record. The register block's records sit at `evals/results/g3-regs-driver/slot-NN/<record name>/` (NN from 21 to 40), under the same structure and reach-folder checks as the timer's, numbered from 21. A record of one case in the other's folder is refused. This changes no record, case, card, document, tool or harness file, and no pinned value of the plan.
