**A surviving mutant's run is in the record (wave 2 close, meeting 2, decision M6; gate W2C23).** Before this change the `must-fail` scorer named a mutant that passed in its summary and dropped its run from both lists of runs, and `must-fail-each` dropped every mutant run that passed a file, so a record's `judge_runs` could not show the run that decided a failed control. Both scorers now list those runs in the score's `runs` (after the clean and cover runs); `failed_runs` is unchanged, and so is every verdict. The runner's check of a claimed pass is unchanged: a pass still needs every run in `runs` recorded as passed, which a passing mutant run is. `tests/test_nirmaan_eval_must_fail.py` shows the run in `judge_runs` with `succeeded: true` for both scorers, and failed before the change. `src/nirmaan/evals/scorers.py` is the pinned group "Held-out scorers" of both committed plans and is in no harness fingerprint, so this moves that group's digest and no fingerprint. No committed record is rewritten; records made before it keep the gap, and each one's verdict is still held by its re-judge.
