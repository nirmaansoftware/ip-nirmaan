**Passing verdicts carry across the loop's merge of main.** main's ruleset "main: two keys" requires up-to-date branches (`strict_required_status_checks_policy` `true`, read with `gh api` on 2026-11-24; the ruleset was last updated 2026-11-22), so each move of main made every open pull request behind, the loop merged main into it, and the verdict cache, keyed by the exact head and main commits, sent both keys and the Founder Proxy back to the start. A founder-class pull request, whose review runs key 1, key 2 and the Founder Proxy one after the other, could so wait through many full reviews (ip#492 did) before one finished with main unchanged. The loop now keeps the heads it asked GitHub to merge main into (state `update_from`), and the review (`carry_basis` in `scripts/pr_review.py`) carries a key's or the proxy's earlier verdict to the new head only when every commit in between is a GitHub update-branch merge of main onto a head the loop updated, the pull request's diff against its merge base is byte-identical to the one the reviewers got, and main's changes since touch none of the pull request's files and no review-control file (CONFIG `carry`). Every key of a run carries from one source, the newest review of the nearest reviewed head, so an older pass never wins over a newer verdict; key 2 carries only when every key-1 result did, and the Founder Proxy only when key 2 did. Only a pass carries; a fail, needs-founder or deferral is reviewed from scratch, fix rounds are unchanged, and CI is never carried: the carry is reached only once the required CI is green on the new head. The carried verdict is posted on the new head with a note naming the head and main it was reviewed on, and logged `carried` (or `carry-refused` with the failed conditions). The loop's header and docs/REVIEW_MECHANISM.md no longer say strict is off. Tests in `tests/test_pr_loop.py` run the real step: a carry for both keys and for the proxy, across two merges while CI ran, and none for an author's own merge, an author's commit after the loop's merge, a changed diff, main touching a file of the pull request or a review-control file, an earlier fail (key 2 then reviewed again too) or needs-founder, a newer fail over an older pass on the same head, a run by hand, or before CI is green.
