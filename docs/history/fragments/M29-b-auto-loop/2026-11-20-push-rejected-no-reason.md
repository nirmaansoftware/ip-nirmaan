**A push GitHub rejects without a reason is retried, not stopped.** When the loop pushed a branch update (the merge of main with the regenerated levels file) and git answered `! [remote rejected] <sha> -> <branch> (failed)`, the loop stopped the pull request for a person, though the same merge pushed by hand a few minutes later went through. The loop now fetches again and pushes the same commit once more; if that is rejected too, the pull request goes into the loop's existing backoff and stops only after the transient retry limit. A rejection that names a reason, a conflict, or a permission error still stops at once.
