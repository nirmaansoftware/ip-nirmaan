**Three pull requests at once.** Founder, in session, 2026-11-23: approved the review loop reviewing up to three pull requests at once. `parallel_reviews` in `LOOP` (`scripts/pr_loop.py`) goes from 2 to 3 and `model_cap` in the review script's `CONFIG` from 2 to 3, so each of the three workers of a pass can hold a model slot; with `parallel_reviews` 1 the pass steps one pull request at a time. Each pull request is still taken by one worker only, and two pull requests listed with one head sha are now stepped one after the other, since the review checks are posted on the head. A pull request's state file and the pause file are now written whole (a temporary file renamed into place), so another worker or the state push never reads half of one. The keys, the Founder Proxy, the fixer, the records fast lane, the merge path, the rate-limit pause and every stop rule are unchanged per pull request. Tests in `tests/test_pr_loop.py` run fake reviewers inside the real step on the real state store, slots and pause file: three at once and never more, a stop on one leaving the others unlabelled, a limit in one worker pausing all, and one worker giving the same results and state as three. On a machine where the Nirmaan loop shares the state folder, its two slots are two of the same three, so at most three model calls run at once across both repositories (docs/REVIEW_MECHANISM.md, "Automated loop").
